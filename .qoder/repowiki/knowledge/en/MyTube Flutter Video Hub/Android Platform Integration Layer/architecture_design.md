Standard Flutter Android application (namespace `com.example.mytube`, minSdk 24, compileSdk/targetSdk 36) with a single `MainActivity` extending `FlutterActivity`. Native capability is split into two independent Flutter plugins registered in `configureFlutterEngine`: `MediaStorePlugin` (channel `com.example.mytube/media_store`) wraps MediaStore queries for system video library access, and `SaffBridgePlugin` (channel `com.example.mytube/saf`) wraps Storage Access Framework tree URIs for external storage traversal. Both plugins implement `FlutterPlugin` + `MethodCallHandler` + `ActivityAware` + an activity-result listener (`RequestPermissionsResultListener` / `ActivityResultListener`) to bridge permission prompts and picker results back to Dart via `MethodChannel.Result`. The plugin layer owns all Android lifecycle and permission handling; Dart communicates exclusively over these two channels. Build is driven by Gradle Kotlin DSL (`app/build.gradle.kts`) with the Flutter Gradle plugin delegating source resolution to the parent project via `flutter { source = "../.." }`.
